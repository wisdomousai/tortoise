# Tool store 4: deployment

The store terminal runs the application on site, with the EAM as its only destination. This part writes the site's deployment policy for the application from [part 3](tool-store-3-connections-and-agents.mdx), builds a signed bundle, installs it under a temporary prefix and removes it again.

## Setup

Open Claude Code or Codex at the root of the exported `tool-store` repository. The check starts with these commands, which end with no errors and `0 fail`:

```sh
bun run format && bun run generate && bun run typecheck
bun test showcase/examples/tool-store
```

## Site deployment

**Goal:** a signed install bundle, installed under a temporary prefix and removed again. **Skills:** [deploy-to-site](../../plugins/site/skills/deploy-to-site/SKILL.md), [decommission-an-application](../../plugins/site/skills/decommission-an-application/SKILL.md).

The application declares what it needs outside the process: the EAM destination, the audit log, the ingress. A deployment policy binds those declarations to one site's addresses and certificates, and the site plugin resolves the policy against the composed catalog, so a destination the policy leaves out is blocked by the egress guard rather than reached. A release is a signed bundle; the site admits it by signature before the install writes the service and firewall files under the prefix. Removal drains the outbox first and refuses the purge while effects remain unresolved, because records waiting for the EAM would be lost. [Security and compliance](../security-and-compliance.md) covers policies, egress and the audit log; [Application lifecycle](../application-lifecycle.md) the shelf life and decommissioning.

```text prompt
Use the deploy-to-site skill and the decommission-an-application skill. In the tool-store
repository, write a deployment policy for the store terminal that binds the EAM destination to
https://eam.plant.example, and disables every other destination. Check it with the site check,
export the network rules, build the CLI, and create, verify and admit a signed bundle with a
throwaway key. Install the bundle under a temporary prefix with no service, show its status,
drain it and uninstall it with purge. Do not apply anything outside the prefix. Report each
command and what it printed, and say which steps only stage on this operating system. Run the
checks the deploy-to-site skill names and report what passed.
```

**Check:** the report lists each command and its output, ending with the uninstall. Nothing outside the prefix changed. On macOS the install writes the service and firewall files but does not load them.

## Limits

Everything in the four parts runs on fakes: no real EAM, scanner, badge reader or model, except Claude Code in the calibration step. These skills need hardware or services a laptop lacks and have no step here: `run-agent-tools-in-a-sandbox` (Linux with bubblewrap), `run-a-hosted-instance` (Postgres and a TLS certificate), `extend-mobile-host` (a phone or emulator), `bridge-station-screen`, `connect-a-site-to-a-fleet` and `write-host-plugin`. [AGENTS.md](../../AGENTS.md#skills) lists the skills.
