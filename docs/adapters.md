# Adapter boundaries

The reference application chooses local Bun/SQLite execution. Feature contracts do not mention these choices. An adapter integrates an external system through an explicit port while preserving the runtime's authorization, transaction and response guarantees.

| Boundary            | Current implementation                              | Required guarantee                                                                                                                           |
| ------------------- | --------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------- |
| Transaction storage | Clone-on-write memory; JSON snapshot SQLite         | Feature state, resource revisions, receipts and journal commit atomically; rejected work commits nothing; reads see one consistent snapshot. |
| Authorization       | Bounded CASL profile and project/task policy        | Operation/object/field checks, pre-pagination scope, current replay/event access and narrowed delegation; unsupported rules fail closed.     |
| Identity/session    | Trusted local owner and scoped host-issued sessions | Principal/workspace/grant come from trusted context, never operation arguments.                                                              |
| Transport           | Loopback HTTP/SSE; host-attached MCP stdio and CLI  | Dispatch through the runtime, preserve structured errors, validate origin/session and protect subscription delivery.                         |
| Harness             | Deterministic fixture; Codex/Claude/AI SDK adapters | Provider types stay private; progress does not imply a business commit; cancellation and recovery state remain explicit.                     |

`Storage<State>` owns `transact(workspaceId, callback)` and `read(workspaceId, callback)`. The core treats feature state as opaque cloneable data, with framework metadata stored beside it. The in-memory adapter isolates copies and serializes work per workspace. `SQLiteStorage` serializes access, uses explicit transactions and validates JSON before storing a versioned workspace document. It is a reference snapshot adapter, not per-table SQL feature repositories. Existing databases must implement equivalent atomic/snapshot behavior rather than independently writing receipts or journal entries after a business commit. Run storage is separate and does not substitute for command receipts.

The CASL adapter accepts equality, membership and boolean conditions over registered scalar fields. Denials are part of the computed scope; arbitrary policy operators and unsupported ordering are rejected. SQL generation parameterizes values and validates registered column names. The example evaluates its small JSON state in memory; SQL scope conformance tests prove the translator's semantics separately. Field restrictions also limit exposed filter/sort choices. Adding a condition operator requires equivalent object, memory and SQL tests before use.

Authorization ports receive trusted context, capability, validated input, current state, phase and previous state at commit. `projectOutput` produces the caller's DTO before schema validation. `canReadEvent` decides whether a minimal resource reference can be delivered. The runtime checks grant operation/expiry/binding and changed-resource restrictions; features apply resource-grant scope to object/list reads. Hosts enforce persisted run revocation through the policy/supervisor boundary. A remote policy adapter must document its revocation consistency; this local implementation does not promise cross-system atomic authorization.

HTTP cursors are encrypted, caller-bound strings. Numeric journal cursors remain private to the host. Restart changes the cursor encryption key, causing a fresh snapshot/reset. `deliverEvents` runs a synchronous enqueue callback under the storage read lock so a local revocation transaction cannot commit between access evaluation and enqueue. Transport adapters must use that boundary rather than asynchronously forwarding a previously authorized batch.

For a different host, inject its identity/policy/storage services and retain the catalog and handlers. For a different transport, adapt requests to `invokeRaw`/`queryRaw` and preserve the error envelope, revisions and authorization state. Do not create independent operation registries or writable workspaces. No cloud-provider adapter is shipped; port separation makes that integration a defined work item, not evidence of a deployed service.
