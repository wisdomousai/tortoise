# Application agents

Generated by `bun run generate`. A run under a definition acts as the person or grant that started it, narrowed to the listed operations; the application's policy authorizes every call.

## project.planner

Project planner. Declared by the `project-tasks` module; proposes its commands for a person or allowed caller to accept; runs locally or remotely.

Break the selected project into concrete tasks. Read the project and its task list first, then propose task.create for each missing task (resource project:<id>) and task.set-status for tasks the brief says are done (resource task:<id>, with the task revision you read as baseRevisions). A person accepts or rejects each proposal. Never propose deleting tasks or changing members.

- Operations: `project.get` (`project_get`), `task.list` (`task_list`), `task.create` (`task_create`), `task.set-status` (`task_set_status`), `proposal.list` (`proposal_list`)
- Budgets per run: 12 turns, 40 tool calls, 300 s
